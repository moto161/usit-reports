# GATE-ADMISSION-ATOMICITY.md

## 目标
证明冻结期间不存在新业务准入窗口，给出 Gate 状态机、准入状态机、原子协议、线性化点。

## 1. 合并原子状态字（唯一权威）

```
_admit_state（单原子字，CAS 更新）：
  - gate 字段：OPEN / FREEZING
  - admit_count 字段：进行中的业务请求数
```

**Gate 与准入计数永不分离更新**。任何「先检查 Gate 再增计数」的分离操作被禁止。

## 2. Gate 状态机

```
OPEN ←──────────┐
  │ CAS freeze  │ CAS unfreeze（回滚）
  ▼             │
FREEZING ───────┘
  │ admit_count==0
  ▼
FROZEN
```

## 3. 准入状态机

```
准入请求 ──CAS(gate==OPEN, admit_count+1)──成功──► 已准入
          └──CAS 失败（gate==FREEZING）────► 拒绝
```

## 4. 原子性协议与线性化点

- **准入线性化点** = `CAS(_admit_state, [gate==OPEN, count+1])` 成功返回点。
- **冻结线性化点** = `CAS(_admit_state, [gate=OPEN → FREEZING])` 成功返回点。

两者操作同一原子字，由 CAS 语义保证**互斥**：

**定理**：冻结 CAS 成功之后，不存在任何新业务准入成功。

**证明**：
1. 准入 CAS 的前置条件是 `gate == OPEN`。
2. 冻结 CAS 成功后，`gate == FREEZING`，此后任何准入 CAS 的前置条件不满足，返回失败。
3. 由于 CAS 是原子的，不存在「冻结已生效但某准入仍读到 OPEN」的中间态。
4. 故冻结线性化点之后，新准入必然失败。

结论：DESIGN_PROVEN（基于 CAS 原子性，属硬件/语言级保证）。

## 5. 十类竞态分析

| # | 竞态 | 结果 | 判定 |
|---|---|---|---|
| 1 | 线程 A 检查 Gate=OPEN，B 冻结，A 随后准入 | A 的 CAS 与 B 的 CAS 竞争同一原子字，仅一个成功 | 无窗口 |
| 2 | 多线程同时申请准入 | CAS 串行化，计数正确 | 无窗口 |
| 3 | 冻结与准入同时发生 | 线性化点唯一，先到者赢 | 无窗口 |
| 4 | 冻结等待期间新请求到达 | gate=FREEZING，CAS 失败拒绝 | 无窗口 |
| 5 | 冻结超时恢复 OPEN，旧请求绕过重检 | 恢复也是 CAS，旧请求需重新 CAS 准入 | 无绕过 |
| 6 | Gate 更新成功但计数未更新 | 不可能（同一原子字） | 无此态 |
| 7 | 计数更新成功但 Gate 更新失败 | 不可能（同一原子字） | 无此态 |
| 8 | 业务异常/崩溃/取消/超时致计数不一致 | 退出时 CAS 减计数，finally 保证 | 计数一致 |
| 9 | 多进程并发 Fork 申请 | coord 锁串行化冻结者 | 单冻结者 |
| 10 | 父子恢复期间收到新请求 | 子进程独立 admit_state，父恢复后重新 OPEN | 隔离 |

## 6. 并发时序图（示意）

```
时间 ──────────────────────────────────────────►
线程A(业务):  [CAS准入 成功]................[CAS退出]
冻结者:            [CAS freeze 成功]  [wait drain]  [快照]  [fork]
新请求:                        [CAS准入 失败·拒绝]
                              ▲
                         冻结线性化点之后，新准入必然失败
```

## 7. 硬性要求满足

- 不采用「先检查 Gate 再增计数」的分离操作。
- 采用合并原子字 + CAS，两者之间**不存在竞争窗口**。
- 故准入原子性可证明，无需降级为 NOT_PROVEN。

## 8. 证据等级
准入原子性：DESIGN_PROVEN（基于 CAS 线性化，属模型级证明）；真实运行时：NOT_TESTED。
