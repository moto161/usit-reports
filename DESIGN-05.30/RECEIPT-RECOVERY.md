# RECEIPT-RECOVERY.md

## 目标
回执恢复协议：只依赖磁盘证据，无法认证时隔离。

## 1. 恢复前置条件

恢复进程必须**仅**依赖磁盘证据，不得凭进程内变量、内存锁状态或假设认定提交成功。

磁盘证据按可信度分层：
1. 回执完整且可认证（D 层）→ 可信。
2. 回执完整但不可认证 → 仅对象匹配证据，不判成功。
3. 回执半成品 → 待恢复，不判成功。
4. current 存在但无回执 → 提交结果未知，隔离。
5. current 不存在 → 未提交。

## 2. 恢复决策表

| 磁盘状态 | 判定 | 动作 |
|---|---|---|
| 回执完整 + 认证通过 + current 匹配 | 提交成功 | 幂等成功 |
| 回执完整 + 认证失败 + current 匹配 | 无法证明创建者 | 隔离 |
| 回执半成品 | 事务中断 | 不删除，待人工 |
| 有 current 无回执 | 提交结果未知 | 隔离，禁止重试 |
| 无 current 无回执 | 未提交 | 安全清理临时文件（仅可证明归属的） |
| 回执与 current 不一致 | 冲突 | 隔离 |
| EEXIST 但归属不明 | 来源不明 | 隔离 |

## 3. 删除/覆盖安全门（任意一项无法证明即 DENY/QUARANTINED）

删除或覆盖任何临时文件、回执、current 前必须确认：
1. 对象身份确认（inode/dev）。
2. 对象类型确认。
3. 文件内容确认（sha256）。
4. 事务归属确认（txn_id/revision）。
5. revision 确认。
6. 对象不是其他事务正在使用。
7. 不存在外部并发修改。
8. 操作结果不处于 UNKNOWN。
9. 删除不破坏已提交数据。

## 4. 崩溃恢复时序

| 崩溃点 | 磁盘可见 | 恢复动作 |
|---|---|---|
| rename 前 | 旧 current | 重新开始或放弃（事务未提交） |
| rename 后 fsync 前 | current 已换但目录项未持久 | rename 结果确认，目录 fsync 重试 |
| fsync 后回执前 | current 已换已持久 | 补写回执（幂等） |
| 回执写入中 | 回执半成品 | 半成品隔离，不判成功 |
| 回执写入后 | 完整回执 | 幂等成功（若可认证） |

## 5. 不变量

- I-RR-1：恢复仅依赖磁盘证据。
- I-RR-2：无法认证的回执不判成功。
- I-RR-3：不确定态不盲目重试。
- I-RR-4：删除/覆盖前满足 9 项安全门。
- I-RR-5：隔离对象不自动清理。

## 6. 证据等级
恢复协议：DESIGN_PROVEN（逻辑）；认证依赖：UNKNOWN；运行时：NOT_TESTED（未执行真实事务）。
