# FORK-LOCK-OWNERSHIP.md

## 目标
7 把锁逐一定义所有权、父子处理、重建规则。区分锁对象内存复制/底层同步原语/OS 锁/线程所有权/进程所有权。

## 1. 概念区分（核心）

- **锁对象内存复制**：fork 时子进程获得父进程锁对象的**逐字节拷贝**，但其底层同步原语状态与父进程**独立**。
- **底层同步原语状态**：threading.Lock / Condition 在 fork 后子进程内状态不确定（可能锁死），必须重建。
- **OS 锁**：flock/fcntl advisory 锁，进程级，fork 后子进程**不继承**（除非特殊设置）。
- **线程所有权**：threading.Lock 由持有线程释放，fork 后子进程只有调用线程存活。
- **进程所有权**：flock/fcntl 归进程，父子不共享。
- **锁重建**：子进程 fork 后重新创建进程本地锁；OS 锁重新获取。

## 3. 关键问题回答

| 问题 | 答案 |
|---|---|
| 子进程可否释放父进程持有的锁？ | 否。子进程锁副本与父进程独立，释放的是子副本，与父无关 |
| 子进程是否可能继承一个永远无法获得的锁状态？ | 是（若 fork 时父持有）。故必须重建，不得沿用 |
| 父释放后子副本是否同步变化？ | 否。父子锁对象独立 |
| 哪些锁必须子进程重建？ | 全部进程本地锁（admit/coord/commit/condvar/业务/身份/Receipt） |
| 哪些 OS 锁必须重新获取？ | POSIX advisory lock（flock/fcntl） |
| 重建失败是否允许继续？ | 否。进入安全终态 |
| 是否存在 fork 前持锁、fork 后父子互等死锁？ | 需证明：父释放自己的锁，子重建自己的锁，互不等待对方锁 |

## 4. 不变量

- I-FLO-1：子进程不释放父进程持有的锁。
- I-FLO-2：fork 后子进程所有进程本地锁必须重建。
- I-FLO-3：父子进程锁状态互不影响。
- I-FLO-4：重建失败进入安全终态，不继续业务。
- I-FLO-5：禁止未持锁释放、跨线程释放、重复释放。
