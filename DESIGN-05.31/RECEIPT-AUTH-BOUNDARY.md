# RECEIPT-AUTH-BOUNDARY.md

## 目标
把 Receipt 认证 UNKNOWN 落实为明确功能禁用边界。

## 1. 认证现状（如实）

- Creator Authentication 未达到可验证状态：**NOT_PROVEN / UNKNOWN**。
- 无可信密钥基础设施：密钥信任根、生命周期、轮换、恢复、撤销均无据。
- 不得将 UNKNOWN 包装为非核心遗留；不得将 QUARANTINED 视为认证成功。

## 2. 认证机制设计（候选，尚未实现）

| 项 | 设计 | 现状 |
|---|---|---|
| 创建者身份认证 | HMAC/数字签名 | 方案正确，密钥基础设施未建立 |
| 认证密钥信任根 | 可信密钥存储（如 TPM/KMS） | 无 |
| 密钥生命周期 | 生成/分发/轮换/撤销 | 无 |
| 密钥丢失处理 | 撤销 + 重新签发 | 无 |
| 密钥轮换 | 定期 + 事件触发 | 无 |
| 密钥恢复 | 备份/分片 | 无 |
| 密钥撤销 | 吊销列表 | 无 |

## 3. Receipt 伪造/复制/替换/重放处理

| 攻击 | 检测 | 处理（认证未建立时） |
|---|---|---|
| 伪造 | 验签失败 | QUARANTINED |
| 复制 | 对象身份/nonce 不匹配 | QUARANTINED |
| 替换 | 内容哈希不匹配 | QUARANTINED |
| 重放 | nonce 一次性校验 | 拒绝 |
| 认证失败 | — | 一律隔离，不判成功 |

## 4. 无法认证时，必须拒绝的操作

| 操作 | 是否拒绝 |
|---|---|
| 事务提交恢复的「幂等成功」确认 | 拒绝（无法认证则不可判成功） |
| 凭回执认定事务已提交 | 拒绝 |
| 自动将 QUARANTINED 转成功 | 拒绝 |
| 删除/覆盖无法认证的回执 | 拒绝 |
| 自动恢复 QUARANTINED | 拒绝（仅人工） |
| 基于回执的跨进程提交确认 | 拒绝 |

## 5. 功能禁用清单及重新启用条件

| 功能 | 状态 | 重新启用条件 |
|---|---|---|
| Receipt 幂等成功确认 | **禁用** | 认证设施建立且验签可验证 |
| 事务提交恢复（凭回执判成功） | **禁用** | 同上 |
| QUARANTINED 自动恢复 | **禁用** | 认证 + 人工审批 |
| 回执跨进程信任 | **禁用** | 认证建立 |
| 回执自动清理 | **禁用** | 认证建立 |

## 6. 硬性规则

1. Creator Authentication 未达可验证状态时，不得宣称 Receipt 协议完整闭合。
2. 不得将 UNKNOWN 包装成非核心遗留。
3. 不得将 QUARANTINED 视为认证成功。
4. 不得自动将未经认证的 Receipt 转为成功事务。
5. 功能禁用清单必须显式维护。

## 7. 证据等级
认证机制：NOT_PROVEN；协议边界：DESIGN_PROPOSAL；运行时：NOT_TESTED。
