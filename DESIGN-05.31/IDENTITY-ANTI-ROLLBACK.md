# IDENTITY-ANTI-ROLLBACK.md

## 目标
解决快照恢复导致身份计数器回滚问题。若无可信防回滚锚点，明确 NOT_PROVEN 并禁用功能。

## 1. 问题定义

05.30 的 `branch_path + local_fork_sequence` 唯一性依赖序号永不回退。但：
- 恢复旧快照会把 `local_fork_sequence` 回退到旧值。
- 回退后再次分配，可能产生与历史**重复**的 fork_event_id。
- 故「严格防回滚唯一性」不成立。

## 2. 候选方案分析（不预设可行）

### 方案 A：可信外部单调计数器（如硬件 TPM monotonic counter / 远程可信服务）
- 信任根：TPM / 远程服务。
- 数据位置：TPM NV / 远程存储。
- 快照恢复能否回滚：否（外部，不受进程快照影响）。
- 崩溃/断电/磁盘恢复/复制快照后唯一：是（外部单调）。
- 多进程并发分配：需远程原子分配。
- 锚点不可用：系统进入 DEGRADED，禁用新身份分配。
- 无法检测的复用路径：若外部计数损坏，理论上存在。
- **当前环境：无 TPM 单调计数器、无远程可信服务 → 不可用。**

### 方案 B：不可回滚的独立持久化锚点（如 append-only 日志 / 一次写介质）
- 信任根：文件系统 + append-only 语义。
- 数据位置：独立锚点文件。
- 快照恢复能否回滚：**是**（快照可覆盖锚点文件）→ 失败。
- 结论：普通文件系统无法提供不可回滚保证，**不成立**。

### 方案 C：外部身份注册 / 租约机制（如 etcd lease / 分布式协调器）
- 信任根：分布式协调器。
- 数据位置：协调器存储。
- 快照恢复能否回滚：否（协调器持有权威）。
- 多进程并发：协调器原子分配。
- **当前环境：无分布式协调器 → 不可用。**

### 方案 D：其他可验证防回滚机制
- 尚无在本只读环境内可验证的机制。

## 3. 结论

**当前环境无可信防回滚锚点。** 随机 UUID、普通文件计数器、普通数据库自增字段均**不能**提供严格防回滚证明。

- 身份防回滚唯一性：**NOT_PROVEN**。
- 依赖防回滚身份的功能：**保持禁用**（见功能禁用清单）。

## 4. 功能禁用清单（身份相关）

| 功能 | 状态 | 重新启用条件 |
|---|---|---|
| 快照恢复后 fork_event_id 防回滚唯一性 | 禁用 | 引入可信外部单调计数器 |
| 跨快照恢复的严格身份唯一性保证 | 禁用 | 引入可信锚点 |
| 基于防回滚身份的跨重启事务关联 | 禁用 | 引入可信锚点 |
| 树内严格唯一性（跨快照场景） | 降级为「单次运行内」 | 引入可信锚点 |

## 5. 保留的有限保证（如实）

- **单次进程运行内**：branch_path + local_fork_sequence 提供结构唯一性（无快照回滚时成立）。
- **跨快照/跨重启**：唯一性 NOT_PROVEN。

## 6. 证据等级

- 单次运行内结构唯一：DESIGN_PROVEN（无回滚前提）。
- 跨快照防回滚唯一：**NOT_PROVEN**。
- 运行时：NOT_TESTED。
