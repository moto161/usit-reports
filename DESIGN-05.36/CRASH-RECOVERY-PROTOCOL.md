# CRASH-RECOVERY-PROTOCOL.md — 崩溃恢复与计数器重置安全证明（05.36）

证据等级：VERIFIED_STATIC（含 NOT_PROVEN 项，如实标注）
目标：修复 05.35 提出的「进程退出后计数随进程消失，恢复时重置为 0」未经证明的问题。

---

## 1. 原子状态字的存储介质 / 作用域 / 生命周期

状态字 `_admit_state` 存在四种作用域，恢复规则各不相同：

| 场景 | 介质 | 作用域 | 进程退出后 | 是否可安全归零 |
|---|---|---|---|---|
| 单进程单线程 | 进程内原子变量 | 进程内 | 随进程消失（内存回收） | 是（无共享写入者） |
| 单进程多线程 | 进程内原子变量 | 进程内（线程共享） | 随进程消失 | 是（线程随进程终止） |
| 多进程 Fork | 写时复制副本 | 每进程独立 | 各自随进程消失 | 是（副本不共享） |
| 跨进程共享 | 共享内存 / mmap | 跨进程 | **可能存活** | **否**（需证明旧写入者停止） |

**强制规则（工单 B36-04）**：不得仅凭「某个进程已经退出」就推定共享计数器可以归零。归零必须满足 §5 的「旧写入者排除证明」。

---

## 2. 进程退出后哪些状态消失、哪些存活

- **自动消失**：进程内原子变量（含线程共享的）、Fork 写时复制副本、栈/堆上的非持久化状态、未落盘的锁句柄。
- **可能存活**：共享内存 / mmap 映射的状态字、已落盘的持久化事务记录（Receipt、Commit 日志）、文件锁（flock/fcntl，取决于实现）。

判断依据是**存储介质的生命周期**，而非「进程是否退出」。这是本协议的核心区分。

---

## 3. 崩溃类型与恢复策略矩阵

| 崩溃类型 | 状态字影响 | 事务影响 | 恢复策略 |
|---|---|---|---|
| 线程异常（被捕获） | 进程内状态字不变 | 该线程事务可能半途 | 线程级清理（finally + 幂等清理），状态字按线程退出递减 count |
| 线程取消 | 同上 | 同上 | 同上 |
| 进程正常退出 | 进程内状态字消失 | 事务已提交/未提交需判定 | 无共享介质则无需恢复；有共享介质则走 §5 |
| 进程崩溃（段错误/杀） | 进程内状态字消失，共享介质存活 | 遗留事务状态不明 | 走 §5/§6，无法证明则 ISOLATED |
| 系统崩溃 / 断电 | 内存全失，磁盘证据可能部分落盘 | 提交可能未 fsync | 走 §6 事务恢复决策树，仅磁盘证据 |
| 快照回滚 / 磁盘恢复 | 内存重载，磁盘回到旧时间点 | 回滚点后事务丢失 | 走 §6，身份防回滚见 IDENTITY 相关约束 |

## 4. 状态字重建流程（仅限「无共享写入者」已证明时）

```python
def rebuild_state_word(evidence):
    if shared_medium_has_live_writers():
        return 'DENY'   # 旧写入者仍存活，禁止重建
    if not all_old_writers_excluded():
        return 'DENY'   # 无法证明旧业务/写入者/异步任务已停止
    # 仅当无共享介质、或已证明所有写入者停止时，才允许归零/重建
    new_count = 0
    for tx in scan_persistent_transactions():
        if tx.state == COMMITTED_CONFIRMED:
            continue        # 已完成，不计入 count
        if tx.state == UNKNOWN:
            return 'DENY'   # 不确定事务不得自动重放或清零
        # 未提交但可安全丢弃的，不计入
    state = GATE_OPEN if allowed else GATE_CLOSED
    state |= DENIED_MASK if denied_evidence else 0   # 保留 DENIED
    commit(state)
```

**核心**：重建/归零的前提是「所有旧写入者已停止」+「无 UNKNOWN 事务」。两个前提任一不满足 → DENY。

---

## 5. 旧写入者排除证明

要证明共享计数器可归零，必须逐项证明：

1. **进程级**：所有可能写入共享状态字的进程已退出或已确认不再写入（通过进程表 + 心跳 + 租约）。
2. **线程级**：所有线程已 join 或已确认终止（通过线程状态）。
3. **异步任务**：后台任务、回调、定时任务已取消或已确认退出。
4. **锁外写入者**：见 WRITE-ENTRY 覆盖清单（历史约束），未覆盖的锁外写入者仍为 UNKNOWN 时，**不得排除**，必须 DENY。

无法完成上述任一证明 → 状态字不得归零，进入 DENY/隔离。

---

## 6. 事务恢复决策树

对每个持久化事务记录，按磁盘证据判定：

```
事务状态？
├─ COMMITTED_CONFIRMED（有落盘确认 + 创建者认证闭合）
│    → 安全，不重放，不计入 count
├─ COMMITTED_UNCONFIRMED（提交已写但无确认）
│    → 状态不明 → 隔离，不自动重放
├─ IN_FLIGHT（进行中，未提交）
│    → 若无活跃写入者且可安全回滚 → 回滚；否则隔离
├─ QUARANTINED（未认证 Receipt）
│    → 保持隔离，不参与成功恢复
└─ UNKNOWN（证据缺失/损坏）
     → ISOLATED，禁止自动重试或放行
```

**强制规则**：
- 不得将 UNKNOWN 事务视为已完成。
- 不得自动重放状态不明的 Commit 或 Receipt 操作。
- 无法确认遗留事务是否已提交时，不得自动重试或放行。

---

## 7. 恢复失败 / 证据缺失 / 状态不一致

任何以下情况 → 保持 DENY / ISOLATED，禁止自动恢复 OPEN：

- 证据缺失（无法判定事务状态）。
- 证据冲突（同一事务出现矛盾记录）。
- 旧写入者无法排除。
- 状态字与磁盘证据不一致。
- DENIED 位存在（重建时显式保留）。

## 8. NOT_PROVEN 边界（如实标注）

以下能力当前**无法证明**，保持禁用，不得改写为 PASS：

- **旧写入者排除的完备性**：对「锁外写入者」的枚举仍为 UNKNOWN，因此跨进程共享场景下，状态字归零的「旧写入者全部停止」证明**不完整** → 共享介质归零路径 NOT_PROVEN。
- **跨快照身份唯一性**：NOT_PROVEN（继承 05.33 结论）。
- **Receipt 创建者认证**：NOT_PROVEN（继承 05.33 结论）。
- **Break-glass 审计信任根**：NOT_PROVEN（继承 05.31 结论）。

**后果**：在无法证明旧写入者已全部停止的环境（尤其是跨进程共享介质）下，Fork 与共享计数器归零保持 DENY。单进程场景（进程内原子变量，进程退出即消失）不涉及共享介质，归零自然安全，此边界在 §1 表格中明确。
